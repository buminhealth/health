## ★ 서버 업데이트 (v18.7) — 이미 1단계를 배포한 뒤 Code.gs만 바꿀 때

화면(GitHub Pages)은 이미 최신입니다. 서버(Apps Script)만 새 버전으로 바꾸면 됩니다.

1. 구글시트 → 확장 프로그램 → Apps Script → `Code.gs` 전체를 이 저장소의 `gas/Code.gs`로 바꾸고 저장
   - 맨 위 부근에 `SERVER_VERSION = 'v18.7` 이 있으면 최신
2. **배포 → 배포 관리 → 기존 웹 앱 ✏(연필) → 버전: `새 버전` → 배포**
   - 코드 저장만으로는 반영되지 않습니다. "새 배포"(새로 만들기)는 주소가 바뀌므로 누르지 마세요
3. 시트 새로고침(F5) → 메뉴 **`④ 인사 사이트(Firebase) 연결`**
   - 1/5: **`https://bumin-leave.web.app`** 입력 (연결 정보 자동)
   - 2/5: 빈칸(firestore 유지) / 3/5: 빈칸(`employees_public`) / 4/5·5/5: 빈칸(저장된 계정 유지)
   - 시험 조회 결과 창에서 "○명을 직원으로 인식" 확인
4. 메뉴 **`⑤ 매일 아침 자동 확인 켜기`**
5. 관리자 모드 → 👥 직원정보관리에서 확인
   - [ ] **서버 버전: v18.7**
   - [ ] **[저장된 계정으로 가져오기]** → 미리보기가 뜸 (경고 창이 뜨면 내용 확인)
   - [ ] **④ 부서 이름 점검표**가 나옴 → "✕ PIN 없음" 부서는 `부서인증` 시트에 PIN·사용 Y 입력
6. 관리자 모드 → 🧪 **물질 마스터 점검** (2단계)
   - ① CAS 문제: 날짜로 바뀐 CAS(예: 9014-01-01) 복원 제안 → 체크된 채로 반영
   - ② 같은 CAS인데 판정이 다른 제품: 함량 확인 후 시트에서 직접 맞추기
   - ③ [기존 판정으로 법령대조표 만들기] → 시트 `법령대조표` 생김 (비고: 고시 확인 필요)
     - 고시 목록(CAS·주기)을 이 시트에 붙여넣으면 그 값이 제안 근거로 우선 사용됨
   - 함량을 보고 맞는 제안만 체크 → [선택한 항목 시트에 반영] (빈 칸에만 기록)
7. 사이트를 한 번 새로 열면(Ctrl+F5) PC 저장소에서 서명·사진이 빠져 용량이 줄어듭니다 (결재 관리 → 용량 표시로 확인)

# 1단계 배포 안내 (v18.1) — 최초 전환 때 사용한 순서 (기록용)

HTML(화면)과 서버(`gas/Code.gs` v2)는 **함께** 바꿔야 합니다. 한쪽만 바뀌면 저장이 실패합니다.
그래서 **A. 준비 단계**(언제 해도 기존 화면에 영향 없음)와 **B. 전환 단계**(업무가 적은 시간, 약 30분)로 나눠 진행합니다.

## A. 준비 단계 — 지금 해도 됩니다 (기존 화면에 영향 없음)

Apps Script는 코드를 고쳐도 **"새 버전으로 배포"(B-3)를 하기 전까지 기존 웹 앱이 그대로 동작**합니다.

### A-1. 백업
- GitHub 저장소 → Code → **Download ZIP** (지금까지의 기록·PDF 전체)

### A-2. 서버 코드 교체
- 구글시트 → 확장 프로그램 → Apps Script → `Code.gs` 내용을 전부 지우고 이 저장소의 `gas/Code.gs`로 바꾼 뒤 **저장**
- (아직 배포하지 않습니다)

### A-3. 초기 설정
시트를 새로고침 → 상단 메뉴 **`보건관리 시스템` → `① 초기 설정`**
- 권한 승인 창이 뜨면 허용 (드라이브 폴더 생성·메일 발송에 필요)
- 관리자 비밀번호(8자 이상) 설정
- **`부서인증` 시트** 입력
  | 열 | 내용 |
  |---|---|
  | 부서 | `직원목록` 시트의 부서 이름과 똑같이 |
  | PIN | 4~6자리 |
  | 사용(Y/N) | `Y` |
  | 부서장 이메일 | 신규입사 알림을 받을 주소 |
- **`관리자설정` 시트**에 자동으로 생긴 값 확인
  | 키 | 기본값 | 설명 |
  |---|---|---|
  | 앱주소 | GitHub Pages 주소 | 메일 [확인하기] 링크 |
  | 보건관리자이메일 | clover8477@bumin.co.kr | 부서장 회신 알림 수신 |
  | 신규입사기준일수 | 7 | 최근 며칠 입사자까지 알림 대상 |
  | 재알림간격일 | 3 | 교육기한이 3일이므로 **1로 바꾸는 것을 권장** |

### A-4. 지난 달 자료 미리 올리기
- ① 초기 설정 안내 창에 나온 **드라이브 폴더**를 엽니다
- ZIP 안의 `교육일지`, `보호구`, `화학물질` 폴더 중 **이번 달을 뺀 지난 달 폴더들만** 올립니다
  (용량이 커서 시간이 걸리고, 지난 달 자료는 더 바뀌지 않으므로 미리 올려도 됩니다)
- 드라이브 안 구조는 GitHub와 같아야 합니다: `교육일지/2026-07/…pdf`

### A-5. (선택) 인사 사이트 자동 로그인 — 나중에 해도 됨
- 메뉴 **`④ 인사 사이트(Firebase) 연결·자동 로그인 설정`**
  - 1/5: 휴직자관리 페이지 소스의 `firebaseConfig = { apiKey: …, projectId: …, databaseURL: … }` 부분 붙여넣기
  - 2/5: 데이터 종류 `firestore` 또는 `rtdb` (코드에 `firestore`가 있으면 firestore, `database`면 rtdb)
  - 3/5: 직원 데이터 위치 (코드의 `collection('…')` 또는 `ref('…')` 안의 이름)
  - 4/5, 5/5: 자동 로그인 아이디·비밀번호 (스크립트 속성에만 저장, 코드·시트에 남지 않음)
  - 저장 직후 시험 조회 결과가 표시됩니다. "이름 열을 찾지 못했습니다"가 나오면 표시된 열 목록을 Claude에게 알려주세요
- 메뉴 **`⑤ 매일 아침 자동 확인 켜기`**
- 설정 전에는 **알림 메일이 나가지 않습니다** (엑셀 붙여넣기로 직원정보만 관리)

2. 보건관리실 PC에서 (Node.js 설치 후) 명령 창: `npx @google/clasp@3.4.1 login` → 병원 구글 계정으로 허용
   - 만들어진 파일 `C:\Users\(사용자)\.clasprc.json` 내용을 메모장으로 열어 전체 복사
3. GitHub 저장소 → Settings → Secrets and variables → Actions
   - **Secrets** → New: 이름 `CLASPRC_JSON`, 값 = 2의 내용 (이 값은 구글 드라이브·스크립트 권한이므로 다른 곳에 붙여넣지 말 것)
   - **Variables** → New: `GAS_SCRIPT_ID` = Apps Script → ⚙ 프로젝트 설정 → 스크립트 ID
   - **Variables** → New: `GAS_DEPLOYMENT_ID` = Apps Script → 배포 → 배포 관리 → 웹 앱의 배포 ID
4. GitHub → Actions → '서버(Apps Script) 배포' → Run workflow 로 한 번 시험
- 끊으려면 시크릿 `CLASPRC_JSON`을 지우면 됩니다. 구글 계정 → 보안 → 타사 액세스에서 clasp 권한도 해제할 수 있습니다.

## 교육 대상 규칙 (v20.3)

- 관리자 모드 → 직원정보관리 → **④ 부서 매칭 · 교육 대상 규칙**
- 시트 `교육대상규칙`(처음 열 때 자동 생성): 사용 · 부서 · 직종 · 판정(대상/제외) · 교육구분 · 물질 · 비고
- 위 줄부터 보고 **처음 맞는 줄 하나만** 적용. 맞는 줄이 없으면 chemicals 시트의 부서 기준.
- 부서: 쉼표로 여러 개, `병동` = 모든 병동, `*` = 전체 / 직종: 직원목록 '직위'에 들어 있는 글자(간호사 · 간호조무사 · 의사 …)
- 일지를 쓴 사람은 규칙으로 제외돼도 이수로 봄. 부서를 옮겨 새 부서 물질 교육이 없으면 다시 대상(1회).

## 직원목록 ↔ 인사 사이트 합치기 (v20.3)

- 관리자 모드 → 직원정보관리 → ① **[인사 사이트와 합치기 (인사 사이트 우선)]** → 미리보기 확인 → [이대로 적용]
- 사번이 `#N/A` · 빈칸 · 숫자 아님 → 사번 없음으로 보고 인사 사이트 사번으로 채움
- 찾는 순서: 사번 → 이름 + 입사일 → (시트 사번이 없을 때) 같은 부서 같은 이름 한 명
- 같은 사번 줄이 여러 개 → 가장 많이 채워진 줄에 합치고 나머지 줄 삭제
- 이름 · 부서 · 입사일 · 재직상태 · 퇴사일 · 이메일 · 직위는 인사 사이트 값이 있으면 그 값으로
- 합친 뒤에도 사번이 없는 사람은 미리보기 맨 아래에 따로 표시 (퇴사했거나 이름이 다른 경우 — 시트에서 직접 확인)
- 인원이 평소보다 크게 줄면(사이트 구조 변경 의심) 경고 후 멈춤. 매일 아침 자동 확인도 같은 규칙으로 합침

## 근무지 지정 · 일괄 수기 이수 (v20.3)

- 한 인사 부서에 여러 작업장이 섞인 경우(예: 외래 = 인터벤션 · 소아과 · 부인과): 교육 현황 → 부서 → 직원 체크 → [근무지 지정…]에서 근무지 선택 → [근무지 적용]
  - 근무지가 정해진 직원은 그 근무지의 물질 · 교육구분(인터벤션센터 = 특별) · 규칙으로 판정 (부서 규칙보다 우선), 시트 `근무지지정`
  - 부서 규칙은 '외래 → 제외'처럼 기본값만 두고, 실제로 취급하는 사람만 근무지를 지정하는 방식 권장
- 일괄 수기 이수: 교육 현황 → [전 부서 일괄 수기 이수] → 부서 고르기 · 기준일 → 미리보기 → 처리 (입사일이 기준일보다 늦으면 입사일로)
  - 부서 하나만: 부서 명단에서 [보이는 직원 전체 선택] → 교육일 → [선택 직원 수기 이수]

## 제외 판정 · 수기 기록 삭제 (v20.3)

- 교육 기록은 지우지 않고 '지금 부서 기준'으로만 판정합니다.

  - 수기(종이) 줄만 삭제 가능 · 앱에서 쓴 서명 일지는 삭제 안 됨
  - 지운 줄은 `교육이력_삭제` 시트에 그대로 옮겨 보관(삭제일시 · 삭제자 · 사유) → 되살리려면 그 줄을 교육이력대장으로 복사
