# 1단계 배포 안내 (v18.1)

HTML(화면)과 서버(`gas/Code.gs` v2)는 **함께** 바꿔야 합니다. 한쪽만 바뀌면 저장이 실패합니다.
그래서 **A. 준비 단계**(언제 해도 기존 화면에 영향 없음)와 **B. 전환 단계**(업무가 적은 시간, 약 30분)로 나눠 진행합니다.

---

## A. 준비 단계 — 지금 해도 됩니다 (기존 화면에 영향 없음)

Apps Script는 코드를 고쳐도 **"새 버전으로 배포"(B-3)를 하기 전까지 기존 웹 앱이 그대로 동작**합니다.

### A-1. 백업
- GitHub 저장소 → Code → **Download ZIP** (지금까지의 기록·PDF 전체)

### A-2. 서버 코드 교체
- 구글시트 → 확장 프로그램 → Apps Script → `Code.gs` 내용을 전부 지우고 이 저장소의 `gas/Code.gs`로 바꾼 뒤 **저장**
- (아직 배포하지 않습니다)

### A-3. 초기 설정
시트를 새로고침 → 상단 메뉴 **`보건관리 시스템` → `① 초기 설정`**
- 권한 승인 창이 뜨면 허용 (드라이브 폴더 생성·메일 발송에 필요)
- 관리자 비밀번호(8자 이상) 설정
- **`부서인증` 시트** 입력
  | 열 | 내용 |
  |---|---|
  | 부서 | `직원목록` 시트의 부서 이름과 똑같이 |
  | PIN | 4~6자리 |
  | 사용(Y/N) | `Y` |
  | 부서장 이메일 | 신규입사 알림을 받을 주소 |
- **`관리자설정` 시트**에 자동으로 생긴 값 확인
  | 키 | 기본값 | 설명 |
  |---|---|---|
  | 앱주소 | GitHub Pages 주소 | 메일 [확인하기] 링크 |
  | 보건관리자이메일 | clover8477@bumin.co.kr | 부서장 회신 알림 수신 |
  | 신규입사기준일수 | 7 | 최근 며칠 입사자까지 알림 대상 |
  | 재알림간격일 | 3 | 교육기한이 3일이므로 **1로 바꾸는 것을 권장** |

### A-4. 지난 달 자료 미리 올리기
- ① 초기 설정 안내 창에 나온 **드라이브 폴더**를 엽니다
- ZIP 안의 `교육일지`, `보호구`, `화학물질` 폴더 중 **이번 달을 뺀 지난 달 폴더들만** 올립니다
  (용량이 커서 시간이 걸리고, 지난 달 자료는 더 바뀌지 않으므로 미리 올려도 됩니다)
- 드라이브 안 구조는 GitHub와 같아야 합니다: `교육일지/2026-07/…pdf`

### A-5. (선택) 인사 사이트 자동 로그인 — 나중에 해도 됨
- 메뉴 **`④ 인사 사이트(Firebase) 연결·자동 로그인 설정`**
  - 1/5: 휴직자관리 페이지 소스의 `firebaseConfig = { apiKey: …, projectId: …, databaseURL: … }` 부분 붙여넣기
  - 2/5: 데이터 종류 `firestore` 또는 `rtdb` (코드에 `firestore`가 있으면 firestore, `database`면 rtdb)
  - 3/5: 직원 데이터 위치 (코드의 `collection('…')` 또는 `ref('…')` 안의 이름)
  - 4/5, 5/5: 자동 로그인 아이디·비밀번호 (스크립트 속성에만 저장, 코드·시트에 남지 않음)
  - 저장 직후 시험 조회 결과가 표시됩니다. "이름 열을 찾지 못했습니다"가 나오면 표시된 열 목록을 Claude에게 알려주세요
- 메뉴 **`⑤ 매일 아침 자동 확인 켜기`**
- 설정 전에는 **알림 메일이 나가지 않습니다** (엑셀 붙여넣기로 직원정보만 관리)

## B. 전환 단계 — 업무가 적은 시간에 (약 30분)

> B-3부터 B-4가 끝날 때까지 몇 분간 기존 화면의 저장이 실패할 수 있습니다. 연달아 진행하세요.

### B-1. 최신 자료 다시 받기
- GitHub → Code → **Download ZIP** (A-1 이후 새로 쌓인 기록 포함)

### B-2. 최신 자료 올리기
- 드라이브 폴더에 **`records` 폴더**와 **이번 달 폴더**(예: `교육일지/2026-10`, `보호구/2026-10`, `화학물질/2026-10`)를 올립니다
- ⚠ **같은 이름의 폴더를 두 번 올리지 마세요.** 드라이브는 같은 이름 폴더를 2개 만들어 오류가 납니다.
  이미 올린 폴더가 있으면 먼저 지운 뒤 다시 올리세요.

### B-3. 서버 배포
- Apps Script → 배포 → **배포 관리** → 기존 웹 앱 ✏ 수정 → 버전: **새 버전** → 배포
- 반드시 **기존 배포를 수정**하세요 (새 배포를 만들면 URL이 바뀌어 화면이 서버를 못 찾습니다)
- 실행 사용자: 나 / 액세스 권한: 모든 사용자

### B-4. 화면 반영
- Claude에게 **"main에 반영해줘"** → `stage1-server-auth` 브랜치를 main에 합침 (GitHub Pages 갱신까지 몇 분)

### B-5. 바로 확인
- [ ] 첫 화면 MSDS 목록이 로그인 없이 보인다
- [ ] 오른쪽 아래 `🔒 부서 로그인` → 부서·PIN 로그인 → 배지에 부서명 표시
- [ ] MSDS 교육일지 탭: 부서가 고정되고, 직원 검색에 그 부서 직원만 나온다
- [ ] 관리자 탭: 관리자 비밀번호 로그인 → 결재 관리에 기존 일지가 보인다
- [ ] 결재 관리에서 기존 PDF 하나를 열어 본다 (드라이브에서 불러옴)
- [ ] 👥 직원정보관리 탭이 열린다

### B-6. 각 부서 안내
- 각 부서장에게 PIN 전달
- 각 PC에서 한 번씩 로그인 (보건관리자 PC는 관리자 모드) → 그 PC에만 남아 있던 기록이 자동으로 서버에 합쳐집니다
